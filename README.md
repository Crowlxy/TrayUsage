# Claude Code / Codex 使用量トレイ

Windows のタスクトレイで Claude Code と Codex の **5 時間・週次の使用率**を確認する小さなアプリです。**画面上端の中央にマウスを置く**か、**Caps Lock を約 0.3 秒長押し**すると、画面上部に使用量のパネルが現れます（Caps Lock はキーを離すと閉じます）。アプリ起動中は Caps Lock の通常の大文字固定を無効にします。待機中は前回の取得完了から 60 秒、パネル表示中は 15 秒で再取得します。パネルを開いたときも、前回の取得から 5 秒以上経っていれば再取得します。トレイメニューから手動更新もできます。サーバーの反映時間と通信時間を伴う定期取得で、完全なリアルタイム更新ではありません。

## 起動

1. [dist/TrayUsage.exe](dist/TrayUsage.exe) を実行します。
2. Caps Lock を長押しして使用量を表示します。短く押した場合も大文字固定は切り替わりません。
3. トレイの使用量アイコン（リングと星）を左クリックするとパネルを 5 秒間表示します。右クリックでメニューを開けます。アイコンが隠れている場合は Windows の「隠れているインジケーター」にあります。アイコンはタスクバーのライト／ダークテーマに合わせて黒と白が切り替わります。
4. 終了するときはメニューの「終了」を選びます。終了後は Caps Lock の通常動作に戻ります。

トレイメニューの「Windows 起動時に実行」で自動起動をオン・オフできます。チェックが付いているときは、現在の EXE がユーザー単位の Windows 自動起動に登録されています。

## 開き方と作業の通知

普段は何も表示しません。次のいずれかで、画面上端中央に島が現れます。

- **マウスを画面上端の中央に置く**（約 0.2 秒静止）。ポインタが島から離れて約 0.35 秒たつと閉じます。ボタンを押しながらの移動（ウィンドウやタブのドラッグ）では開きません。
- **Caps Lock の長押し**、または**トレイアイコンの左クリック**。

島の形は**テーマ**で切り替えられます（トレイメニューの「テーマ」）。既定の **Classic** は画面上端に付いてぶら下がる形で、付け根が外側へ滑らかに広がります。**Pill** は上端から少し離れて浮かぶカプセルです。

島には「Usage」「Running」「Done」の 3 つのタブがあり、右上に時計（時刻と日付）と歯車アイコンがあります。タブのクリックかマウスホイールでページを切り替え、歯車（またはトレイメニューの「設定…」）で設定ページを開閉します。設定ページでは各種通知・進捗表示・全画面時の抑止・上端ホバーとその待ち時間・テーマ・時計・自動起動をその場で切り替えられます（トレイメニューと同じ設定です）。ページを切り替えても見出しの文字は動かず、本文だけがその場で入れ替わります。使用量ページのロゴには、最も使っている枠の使用率を示すリングが付きます。閉じるときは内容が縮みながら薄れ、カプセルの大きさに収まってから消えます。「Running」には実行中のセッション（経過時間）が、「Done」には最近完了したもの（所要時間と完了時刻）が、それぞれ最大 5 件並びます。実行中のセッションのロゴの周りを、弧が回ります（質問待ちのときは止まって橙の点になります）。ロゴの周りだけをフレームごとに描くので、本文の再描画は起きません。自前の描画で、Agent HUD のボットや Clawd は使っていません。島の表示は英語、設定ページとトレイメニューは日本語です。開閉の動きは macOS の Dynamic Island に合わせています（開くときは弾むバネ、閉じるときは弾まないバネで、中身が先に消えてから窓が薄れます。中身はぼかしと縦の圧縮から戻って現れます）。10 分以上かかった作業の完了は「finished a long task」として長めに表示し、Claude のプラン承認待ち（ExitPlanMode）は「has a plan ready」、API エラーで止まったときは「stopped on an error」、使用量の上限に当たったときは「hit its usage limit」と通知します。

Claude Code / Codex の作業が終わると、島が完了カプセル（緑のチェック、プロジェクト名、所要時間）として自動で現れ、約 4.5 秒後に閉じます。通知の種類は完了のほか、質問待ち（青）、使用量の警告（80% と 95% で黄・赤、100% で「使い切り」）、リセット（水色）があり、種類ごとの色で縁が光ります（警告は二度脈打ちます）。複数が重なったときは順番に表示します。質問待ちはログの `AskUserQuestion` / `request_user_input` が未回答の間を検知します（「作業」ページにも「質問待ち」と出ます）。リセットは、取得した枠のリセット時刻が次のサイクルへ進み、使用率が下がったとき（または使用率が 25 ポイント以上急に下がったとき）に通知します（タイマーが 0 になっただけでは通知せず、取得に失敗した値は使いません。アカウントの切り替えは判別していません）。**承認待ち（Approval）はログに残らない**ため、既定では通知しません。設定ページの「承認待ちを通知（Hook を設置）」をオンにすると、アプリが Claude Code のユーザー設定（`settings.json`、`CLAUDE_CONFIG_DIR` があればそちら）に **Command Hook** を追加します: `PermissionRequest`（承認ダイアログが出た瞬間。承認待ちとして表示）と、`Notification` の `elicitation_dialog`（MCP の入力フォーム。質問として表示）。`Notification` の `permission_prompt` は約 6 秒遅れ、すぐ承認すると出ないことがあるため使いません。Hook は観測だけです。この EXE を `--hook claude` で呼び、イベントを `%LOCALAPPDATA%\TrayUsage\events` に書いて終了します（何も出力せず、常に終了コード 0、タイムアウト 5 秒）。許可の判断は一切返さないので、承認操作には影響しません。Hook が失敗しても（EXE が無い、Git Bash が無いなど）、Claude Code では非ブロッキングのエラー扱いで、承認はそのまま行えます（終了コード 7 を返す Hook でセッションが継続することを Claude Code 2.1.312 で確認）。コマンドは文字列形式で、パスは `/` 区切りです。公式の `command` + `args` 形式は 2.1.312 では `args` が無視された（EXE が引数なしで起動した）ため使っていません（引数なしで起動しても、多重起動の防止で何も起きません）。ほかの Hook や設定はそのまま残し、初回だけ `settings.json.trayusage.bak` に退避します（トークンを含み得るため、現在のユーザーだけが読める権限にします）。読み込めない `settings.json` は変更しません。オフにすると追加した分だけを取り除き、EXE を移動した場合は次回起動時に Hook のパスを自動で直します。Codex 向けの Hook は未対応です。 `TrayUsage.exe --demo` で各種の見た目を順に確認できます。ポインタを乗せている間は閉じません。通知（完了・質問待ち・承認待ち・実行中・使用量の警告やリセット）をクリックすると、島がその通知の詳細カードに広がります。カードの中身は通知によって違います。質問（プラン待ちを含む）・エラー・使用量の上限到達は 2 画面で、1 画面目に要点（依頼文の 1 行、エラーコードやリセット時刻の見出し、返答、質問の選択肢やプランの手順を細い罫線で区切った行）、2 画面目に数字（所要時間・時刻・コンテキストのトークン量・モデルのうち 3 つ、よく使ったツールの細いバー、ブランチ）が並びます。完了・実行中・承認待ちは数字の 1 画面だけ、使用量の警告・使い切り・リセットはメーターの 1 画面だけです。どれも使用量パネルと同じ、箱のない細いメーターと余白で作っています。2 画面のカードは下の点が現在位置で、クリックで次の画面へ進み、最後の画面でのクリックで閉じます（ホイールでも切り替えられます）。これらはセッションのログ（依頼文・返答・`usage`・`gitBranch`・ツール呼び出し）から読み取ります。操作がないまま 15 秒たつと自動で閉じます。カードが出ている間に届いた通知は、閉じたあとに順に表示します。ターミナルへの移動は、複数のウィンドウやタブで使うと行き先を特定できないため、通知からは行いません。「Running」「Done」ページの各行をクリックすると、そのセッションのウィンドウを前面に出せます。ポインタを乗せた通知は少し浮き、手の形のカーソルになります。通知にポインタを置いてもパネルは開きません（クリックを優先するため。上端中央のホバーは従来どおりです）。セッションの特定は、Claude Code の `~/.claude/sessions/<pid>.json`（プロセス ID・セッション ID・フォルダ）か、同じフォルダで動いている `codex` / `claude` プロセスから行い、そのプロセスの親をたどって最初にウィンドウを持つものを前面に出します。Windows Terminal のように 1 つのウィンドウに複数のタブがある場合、タブの選択まではできず、ウィンドウ全体を前面に出します。上端のホバーはトレイメニューの「上端ホバー」でオフにするか、開くまでの待ち時間（0.12 / 0.22 / 0.4 秒）を選べます。ゲームや動画などの全画面アプリが前面にあるときは、作業の通知を出しません（「全画面アプリ中は通知しない」で変更できます）。トレイメニューの「実行中の進捗を表示」をオンにすると、作業中も小さなカプセル（スピナーと経過時間）を出し続けます。既定ではオフです。「完了を通知」は既定でオンです（設定は `HKCU\Software\TrayUsage` に保存）。

hooks や設定の追加は不要です。1.5 秒ごとに、直近 10 分以内に更新されたセッションログを調べます。ログは前回から追加された分だけを読み、行ごとの文字列は作らないため、常駐中のメモリはほぼ増えません（タスクマネージャーの「メモリ」で約 25MB）。

- Claude Code: `~/.claude/projects/*/*.jsonl`（`CLAUDE_CONFIG_DIR` があればそちら）。最後の応答が `end_turn` なら完了、ツール実行中やユーザー入力直後は実行中です。Esc での中断は通知しません。サブエージェントのログは見ず、親セッションの状態で判定します。
- Codex: `~/.codex/sessions/**/rollout-*.jsonl`（`CODEX_HOME` があればそちら）。`task_started` / `task_complete` イベントで判定します。guardian レビューなどの補助スレッドは対象外です。
- 起動した時点で既に終わっているセッションは通知しません。見ている間に実行中から完了へ変わったものだけを通知します。
- ログに現れない状態は判別できません。許可の確認待ちは「実行中」のまま表示され、10 分以上ログが更新されないセッションは表示から外れます（完了通知も出しません）。

この配布ファイルには [.NET 10 デスクトップ ランタイム](https://dotnet.microsoft.com/download/dotnet/10.0) が必要です。Claude Code と Codex CLI にそれぞれログイン済みで、`codex` コマンドが PATH にあることも必要です。再ビルドする場合は `dotnet publish TrayUsage/TrayUsage.csproj -c Release -r win-x64 --no-self-contained -o dist` を実行します。アイコンは [Usage.png](Usage.png) から `python tools/make_icons.py Usage.png TrayUsage/Assets preview.png` で生成します（Pillow・numpy・scipy が必要）。余白を詰め、16〜24px では細い弧を太らせつつ弧の切れ目を 1px 以上残すよう加工しています。

## 取得方法と注意点

- Codex はインストール済み CLI の `app-server` に `account/rateLimits/read` を送信します。[Codex のプロトコル](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/common.rs)にある読み取り操作です。
- Claude Code はローカルの `~/.claude/.credentials.json` にある Claude の OAuth アクセストークンを読み、Anthropic の使用量エンドポイントに問い合わせます。このエンドポイントは公開された安定 API ではないため、仕様変更や認証期限切れで取得できなくなる場合があります。トークンはアプリ側に保存・表示せず、Anthropic 以外へ送信しません。トークンが無い・期限切れ（HTTP 401）のときは、Claude Code 本体（`claude -p --input-format stream-json`）に `get_usage` を問い合わせる方式に切り替えます（Claude Code 自身がトークンを更新するため、再ログインが不要になります。[Agent HUD](https://github.com/jazzenchen/agent-hud-open) と同じ経路で、実測 約 1.7 秒）。常用は軽い HTTP のままです。エンジンの問い合わせは、プロセスを起動するため 3 分に 1 回まで（失敗後は 5 分）に制限し、その間は直前の値を表示し続けます。
- Claude Code の認証ファイルは Claude Code と同じ順序（`CLAUDE_SECURESTORAGE_CONFIG_DIR`、`CLAUDE_CONFIG_DIR`、`~/.claude`）で探します。HTTP 429 が返った場合は `Retry-After` に従って問い合わせを控えます。
- Codex への問い合わせには、プロトコルがバックグラウンドの定期取得向けに定めている `excludeResetCreditDetails` を指定しています。
- 通信エラーやタイムアウト、429 などの一時的な失敗では、前回取得できた値を「HH:mm の値 · 再試行中」として表示し続けます。
- 表示する数値は**使用率**です。5 時間枠がアカウントに返されない場合は「データなし」と表示します。Codex のサーバーが週次枠だけを返す事例も[報告されています](https://github.com/openai/codex/issues/41553)。
- 島の見た目と動きは [Oyenza Studio](https://github.com/lucacadalora/oyenza-studio)（MIT License）の設計を参考にしています。幅・高さ・角丸・上端からの距離をそれぞれ別のばねで動かし、広がるときは幅が先に、縮むときは高さが先に動きます。内容は形が決まりかけてから少し遅れて 2px 沈みながら現れ、入れ替わるときは古い内容が縮みながら消えます。影は広がりのある落ち影と接地影を重ねたものです。細いハイライトと連続曲率の角丸、モニターごとの表示スケール対応、Windows のアニメーション設定オフ時の変形省略は従来どおりです。コマ送りはディスプレイのリフレッシュ（DWM の垂直同期）に合わせ、内容の位置は動いている間だけ小数ピクセルで描くので、ばねの動きが途切れません。タブの強調はばねで滑らかに移動し、使用量のバーは開くたびに伸びて、使用率が 70% 以上で黄、90% 以上で赤になります（色の段階は [Agent HUD](https://github.com/jazzenchen/agent-hud-open)（Apache-2.0）の考え方を参考にし、コードは使っていません）。パネルを開いている間だけクリックを受け付け、通知や待機中はクリックを透過します。Claude と Codex のアイコンはそれぞれ [Claude Code](https://marketplace.visualstudio.com/items?itemName=Anthropic.claude-code) と [Codex](https://marketplace.visualstudio.com/items?itemName=OpenAI.chatgpt) の公式 VS Code 拡張に同梱された画像を使用しています。出典とライセンスは [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) に記載しています。


表示のフォントは Noto Sans JP です（Google の SIL Open Font License。同梱はせず、インストール済みのものを使います。無い PC では Segoe UI に戻ります）。

通知のアイコンは種類ごとの色の円（警告は黄色の ⚠ の三角）で、右下に Claude Code / Codex のロゴを重ねて、どちらのセッションか一目で分かるようにしています。詳細カードは、ポインタがカードから離れると閉じます。
